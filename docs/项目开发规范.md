## 1. 平台抽象：所有平台宏集中在 platform/

**核心思想**：业务代码不得包含 `#ifdef _WIN32` / `#ifdef __linux__` 等平台宏，所有平台差异通过 `platform/` 模块的函数调用实现。

```cpp
// ❌ 错误：业务代码中出现平台宏
#ifdef _WIN32
    SetConsoleOutputCP(CP_UTF8);
    SetConsoleCP(CP_UTF8);
#endif

// ✅ 正确：调用 platform 封装
platform::SetConsoleUtf8();
```

**目录结构**：
```
main_src/base/platform/
├── platform.h          # 统一入口 + 平台常量 (kIsWindows/kIsLinux/kIsMacOS)
├── platform.cc         # 所有 #ifdef 集中实现
├── input_handler.h     # 终端输入抽象接口
├── input_handler_posix.cc   # POSIX 实现（Linux/macOS）
└── input_handler_win32.cc   # Windows 实现
```

**规则**：
- 所有 `#ifdef` / `#if defined` / `#elif defined` 只能出现在 `platform/` 目录下
- 业务代码通过 `platform::NamespaceFunction()` 调用平台功能
- 源文件级平台分离（如 `input_handler_posix.cc` vs `input_handler_win32.cc`）通过 CMake `if(WIN32)` 选择编译，不需 `#ifdef` 包裹
- 新增平台差异功能 → 在 `platform.h` 声明，在 `platform.cc` 用 `#ifdef` 实现

## 2. SDL/ImGui/UI 封装规范

**核心思想**：SDL/ImGui 统一封装在 `media_engine` 下，外部模块禁止直接依赖。

**统一对外接口原则**（Facade 模式）：每个内部结构复杂的模块只暴露一个统一入口头文件，外部只通过该头文件访问模块功能。内部头文件视为私有实现，外部禁止直接包含。

```cpp
// 每个对外模块遵守一个入口头文件的约定：
media_engine/    → media_engine/media_engine.h
prosophor_core/  → prosophor_core/agent_engine.h
```

| 模块 | 对外头文件 | 禁止直接包含 |
|------|-----------|-------------|
| media_engine | `media_engine/media_engine.h` | `media/media_core.h`, `media/drawer.h` 等 |
| prosophor_core | `prosophor_core/agent_engine.h` | `core/agent_core.h`, `managers/*.h` 等 |

```cpp
// ❌ 错误：外部模块直接包含模块内部头文件
#include "media_engine/media/drawer.h"
#include "prosophor_core/managers/agent_session_manager.h"

// ✅ 正确：只包含统一入口头文件
#include "media_engine/media_engine.h"
#include "prosophor_core/agent_engine.h"
```

```cpp
// ❌ 错误：业务代码直接包含 SDL/ImGui
#include <SDL.h>
#include "imgui.h"

// ✅ 正确：通过 media_engine 封装接口
#include "media_engine/media_engine.h"
```

**依赖方向规则**：
```
media_engine → 只能依赖 common/、platform/ 和第三方库 (SDL, ImGui)
scene/       → 只能依赖 media_engine 封装的接口
core/        → 只能依赖 common/、providers/ 和 platform/，不能依赖 media_engine
virtual_sprite/components/ → 只能依赖 media_engine 封装的接口
```

**media_engine 对外暴露规则**：
- 外部模块只能包含 `media_engine/media_engine.h` 统一入口
- 禁止外部模块直接 `#include "media_engine/xxx.h"`（如 `media_engine/media/colors.h`）
- `colors.h` 等内部头文件通过 `media_engine.h` 间接暴露，禁止从 `virtual_sprite/`、`prosophor_core/` 等外部模块透传

```cpp
// ❌ 错误：外部模块直接包含 media_engine 内部头文件
#include "media_engine/drawer.h"
#include "media_engine/imgui_widget.h"

// ✅ 正确：只包含统一入口
#include "media_engine/media.h"
```

**media_engine namespace 规则**：
- `media_engine/` 目录下的所有文件（.h 和 .cc）统一使用 `namespace media_engine { ... }`
- 外部消费者文件（`scene/`、`virtual_sprite/` 等）必须使用 `media_engine::` 显式前缀访问 media_engine 中的类型
- 禁止在外部消费者文件中使用 `using namespace media_engine;`（包括 .cc 文件）
- 外部消费者头文件同样使用 `media_engine::` 前缀，不得 forward-declare media_engine 类型于全局命名空间

```cpp
// ❌ 错误：外部文件使用 using namespace
namespace prosophor {
using namespace media_engine;  // 禁止
    ...
    MediaCore::Instance()...
}

// ✅ 正确：显式前缀
namespace prosophor {
    ...
    media_engine::MediaCore::Instance()...
}
```

**UI 组件设计原则**：
- 通用 UI 组件（ScrollWindow、Button、Slider）→ `media/imgui_widget.h`
- 业务特定组件（ChatPanel、InputPanel）→ `virtual_sprite/components/`
- SDL 常量封装 → `SdlKeys::ESCAPE` 替代 `SDLK_ESCAPE`

**prosophor_core 对外暴露规则**：
- 外部模块只能包含 `prosophor_core/agent_engine.h` 统一入口
- 禁止外部模块直接 `#include "prosophor_core/managers/xxx.h"`、`#include "prosophor_core/core/xxx.h"` 等内部头文件
- `agent_engine.h` 是 frontend（`virtual_sprite`、`ai_coding`、服务器）与 core 交互的唯一接口

```cpp
// ❌ 错误：直接包含 prosophor_core 内部头文件
#include "prosophor_core/managers/agent_session_manager.h"

// ✅ 正确：只包含统一入口
#include "prosophor_core/agent_engine.h"
```

## 3. 时间模块 (time_wrapper)

**核心思想**：时间相关代码统一封装在 `common/time_wrapper` 中。

```cpp
namespace prosophor {
std::tm GetLocalTime(std::chrono::system_clock::time_point time_point = ...);
std::string FormatTimestamp(std::chrono::system_clock::time_point time_point = ..., const char* format = "%Y-%m-%d %H:%M:%S");
std::string GetCurrentTimestamp();  // "YYYY-MM-DD HH:MM:SS"
std::string GetCurrentDate();       // "YYYY-MM-DD"
int64_t GetCurrentTimeMillis();
std::string GenerateIdWithTimestamp(const std::string& prefix);
}
```

```cpp
// ❌ 错误：业务代码中直接使用 chrono
auto now = std::chrono::system_clock::now();
auto millis = std::chrono::duration_cast<...>(now.time_since_epoch()).count();

// ✅ 正确：使用封装的接口
std::string id = GenerateIdWithTimestamp("task_");
int64_t ts = GetCurrentTimeMillis();
```

## 4. 文件工具 (file_utils)

**核心思想**：统一的文件读写、路径操作、JSON 序列化接口。

```cpp
namespace prosophor {
// 路径操作
std::string ExpandHome(const std::string& path);
bool EnsureDirectory(const std::string& path);

// 文件读取
std::optional<std::string> ReadFile(const std::string& path);
std::optional<nlohmann::json> ReadJson(const std::string& path);

// 文件写入
bool WriteFile(const std::string& path, const std::string& content, bool append = false);
bool WriteJson(const std::string& path, const nlohmann::json& json, int indent = 2);

// 存在性检查
bool FileExists(const std::string& path);
bool DirExists(const std::string& path);
}
```

```cpp
// ❌ 错误
std::ofstream file(path);
file << json.dump(2);

// ✅ 正确
WriteJson(path, json, 2);
```

## 5. 消除冗余包装函数

**原则**：不要创建简单的透传包装函数。

```cpp

class SessionManager {
    std::string GetTimestamp() const {
        return GetCurrentTimestamp();
    }

// ✅ 正确：直接使用封装好的接口
current_metadata_["created_at"] = GetCurrentTimestamp();
```

## 7. 命令注册模式 (CommandRegistry)

**核心思想**：所有 slash 命令通过注册方式管理，避免 if/else 链。

```cpp
struct Command {
    std::string name;
    std::string description;
    std::string usage;
    std::vector<std::string> aliases;
    std::function<CommandResult(const CommandContext&, const std::vector<std::string>&)> handler;
};

class CommandRegistry {
public:
    void RegisterCommand(const Command& cmd);
    CommandResult ExecuteCommand(const std::string& name, ...);
};
```

## 8. UI 组件数据与框架分离

**核心思想**：UI 组件仅作为视图层，通过 `std::function` + Lambda 从数据源获取数据。

```cpp
// ✅ 正确：std::function + Lambda 方式
class ChatPanel {
    using MessageGetter = std::function<std::tuple<std::string, std::string>(size_t)>;
    using MessageCountGetter = std::function<size_t()>;
    
    void RenderContent(MessageCountGetter get_count, MessageGetter get_message);
}

// 调用方使用 Lambda 绑定数据源
chat_panel_->RenderContent(
    [this]() { return session_->messages.size(); },
    [this](size_t i) { 
        const auto& msg = session_->messages[i];
        return std::tuple{msg.role, msg.text()};
    }
);
```

**架构分层**：
```
数据层：AgentSession.messages（存储）
          ↓ Lambda 捕获
视图层：ChatPanel（渲染，依赖 std::function）
控制层：UIRenderer（Lambda 绑定 session → ChatPanel）
```

## 10. 控制流规范

**核心思想**：if/else 分支无论多短，必须使用大括号。

```cpp
// ❌ 错误：无大括号
if (condition) do_something();
else do_other();

// ❌ 错误：单行省略大括号
if (condition)
    do_something();

// ✅ 正确：始终使用大括号
if (condition) {
    do_something();
} else {
    do_other();
}
```

**原因**：无大括号的单行分支容易在后续维护时引入 bug（添加第二行却忘记加括号），且调试时不方便断点。

## 11. 测试数据规则：基于真实日志离线化

**核心思想**：测试用例的输入输出必须采集自真实 API 响应日志，不得手造数据。

```cpp
// ❌ 错误：手造数据
handler.OnLine(R"({"message":{"role":"assistant","content":"你好"},"done":true,"done_reason":"stop"})");

// ✅ 正确：从 simulation_bag/*.log 中提取的原始响应
handler.OnLine(R"({"model":"gemma4:e4b","created_at":"...","message":{"role":"assistant","content":"","thinking":"The"},"done":false})");
```

**规则**：
- 测试数据来源：`simulation_bag/*.log` 中的原始 API 响应
- 不可篡改响应内容（可裁剪多余字段保持可读性，但不能改变语义）
- done 行必须验证 `stop_reason`/`usage`，content 行必须验证累积结果
- 离线化：不依赖 API 服务，所有数据硬编码在测试文件中

## 13. 成员变量规范

**核心思想**：成员变量用 `_` 后缀标记，通过 private + getter/setter 封装，头文件内联函数显式标注 `inline`。

```cpp
// ❌ 错误：无后缀、public 直接暴露
class AgentSession {
public:
    std::string sessionId;
    AgentRole* role;
    void SetRole(AgentRole* r) { role = r; }
};

// ✅ 正确：_ 后缀、private、getter/setter、inline
class AgentSession {
public:
    inline const std::string& GetSessionId() const { return session_id_; }
    inline AgentRole* GetRole() const { return role_; }
    inline void SetRole(AgentRole* r) { role_ = r; }
private:
    std::string session_id_;
    AgentRole* role_ = nullptr;
};
```

**规则**：
- 所有成员变量以 `_` 结尾（如 `stop_requested_`），与函数名/参数名区分
- 所有成员变量声明为 private，通过 `GetXxx()` / `SetXxx()` 访问
  - 只读字段（如 `session_id_`, `created_at_`）只提供 Getter
  - 布尔字段读用 `IsXxx()`（如 `IsStopRequested()`），写用 `SetXxx()` 或语义化方法（`RequestStop()`）
- 函数对象类型（`ToolExecutorCallback`、`SessionOutputCallback`）可保留 public，避免 `GetXxx()(args)` 双括号调用
- 头文件中内联定义的函数须显式添加 `inline` 关键字

## 15. UI 组件化架构：渲染层只提供组件，上层只做组合

**核心架构分层**：

```
media_engine/    → 基础组件（Button, Panel, ScrollWindow, InputText 等）
virtual_sprite/components/ → 业务组件（ChatPanel, SpeechBubble, StatusBar 等）
scene/           → 页面组合（用已有组件拼装 UI 布局）
```

**规则**：
- `media_engine/` 中的组件是**最底层的可复用 UI 构建块**，不得直接调用 `DrawFilledRoundRect`、`DrawFilledTriangle` 等绘制原语
- `virtual_sprite/components/` 中的业务组件只能组合 `media_engine/` 的组件，不得自己写绘制代码
- `scene/` 负责布局和组合，只调组件接口，不碰绘制细节

```cpp
// ❌ 错误：业务代码直接调用绘制原语
imgui_widget::DrawFilledRoundRect(x, y, 22, 22, 4, kCloseBtn);
imgui_widget::DrawTriangleOutline(...);

// ✅ 正确：使用组件
TitleBarButton btn("x", onClick);
btn.Render(x, y);
```

**判断标准**：
- 一个 `.cc` 文件中出现 `DrawFilled`/`DrawTriangle`/`DrawRound` 等绘制调用 → 说明缺少组件抽象
- 新增 UI 时如果找不到可复用的组件 → 先在 `media_engine/` 创建组件，再在上层使用
- 颜色、圆角大小、文字偏移量等视觉参数在组件定义中集中管理，上层不出现魔法数值

**架构校验**（review 必查）：
- [ ] 新增 UI 代码是否直接调用了绘制原语？
- [ ] 如果是，应该提取到 `media_engine/` 还是能用现有组件组合？
- [ ] 颜色/圆角/间距常量是否统一，没有在每个文件中重新定义？
